## C. Catalog Architecture

### Authoritative source

The source-of-truth definition list is:

```text
apps/api/src/data-operations/registry/governance-dataset.registry.ts
```

The persistent `GovernanceDataset` table is the durable catalog consumed by later phases. The static definition list prevents user input, display names, table names, or runtime reflection from becoming dataset identity.

### Dataset identity

`datasetKey` is globally unique, stable, machine-readable, and independent of display name or physical model name.

### Classification

The implementation uses the exact frozen M47.1 enum values:

```text
PUBLIC
INTERNAL
CONFIDENTIAL
RESTRICTED
```

The earlier proposed `FINANCIAL_LEDGER` value was not present in the locked schema and was not introduced. Financial datasets use `RESTRICTED` plus explicit `metadata.financialFacts = true` and `IMMUTABLE_FINANCIAL_RETAIN`.

### Deletion strategy

The implementation uses the existing M47.1 values:

```text
HARD_DELETE
ANONYMIZE_PII
IMMUTABLE_FINANCIAL_RETAIN
```

No deletion, anonymization, or retention execution is implemented.

### Retention applicability

Each authoritative definition explicitly sets `retentionApplicable`. No retention duration is stored in the catalog.

### PII metadata

Each definition explicitly declares `containsPii` and `containsSensitiveData`. No sample records or raw PII are stored in catalog metadata.

### Prisma model mapping

Where applicable, a definition contains an explicit `modelName` mapping. The logical `datasetKey` remains authoritative and is not derived from the model name.

The current service validates the static mapping contract but does not use dynamic imports, reflection, dynamic SQL, or code generation.

## E. Completeness Validation

`GovernanceCatalogService.validateDefinitions()` deterministically validates:

- duplicate dataset keys
- duplicate Prisma model mappings
- explicit enum classification
- explicit deletion strategy
- PII/anonymization consistency

`validateCompleteness()` returns:

- the authoritative governed dataset keys
- explicit non-governed technical persistence reasons
- unresolved generated Prisma model delegates not yet semantically classified

This avoids fragile runtime Prisma reflection and makes exclusions reviewable. Full automatic proof that every Prisma model is classified is intentionally not claimed.

## F. Authorization

No new permission strings were added because no runtime mutation/read endpoint was introduced.

## G. Bootstrap / Seed

`GovernanceCatalogService.bootstrap()` provides deterministic, idempotent persistence using `governanceDataset.upsert` keyed by `datasetKey`.

It:

- validates the static definitions first
- creates missing catalog entries
- updates existing catalog metadata by stable key
- does not delete unrelated records
- does not mutate tenant policies
- does not create duplicate dataset definitions

The existing Prisma seed script was not modified. No automatic production bootstrap was added; later deployment/bootstrap work can explicitly invoke the service according to governance decisions.
